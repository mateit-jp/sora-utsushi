## 0. この記録の使い方

- 計画書の「受入条件」「付録A」「第12章の決定」を満たしたことを、**出力つきで**残す記録。計画書 0.3 の完了の定義の 5・7 と、3.4 の前提「#2・#6 の行がある」の答えがここにある。
- 状態は次の三つで書く。**「読めなかった」を「無い」「0件」と書かない。**「未確認」は「まだ確かめていない」で、「無い」ではない。
  - **確認済み**: 出力か画面で確かめた。後ろに（出どころ・日付）を付ける。例: 確認済み（公開 API・2026-10-24）
  - **未確認**: まだ確かめていない
  - **読めなかった**: 取りに行って取れなかった（権限・通信・中継の制限など。理由を書く）
- 出どころの書き方: 「公開 API」＝認証なしで読める GitHub の公開情報を読むだけ／「クラウドの指示文」＝クラウドの Claude Code からの 2026-10-24 の報告を、この記録の作成時に写したもの（出力そのものは未貼付のものがある）／「報告」＝その写し。
- 書かないもの（計画書 6.2）: 個人名・個人のメールアドレス・機体名・私的な置き場・業務の名前。書いてよいのは、公開の連絡先として決めた屋号の Gmail と、コミットに出る noreply のアドレスだけ。`gh auth status` の全文は貼らない（貼るのは `gh api user --jq .login` の1行だけ）。
- 確認のコマンドはパイプに繋がず、1行ずつ流して `rc` を単独で取る。
- 追記の決まりは 8 章。
- ★第2版（2026-10-25）: 店主がアカウント名を mateit-jp に変え、リポジトリを作り直した。それより前の名前の確認と、削除したリポジトリの状態はこの版に写さない（手元の第1版に残る）。

## 8. 追記の決まり

- 追記は PR で行う（main には ruleset を入れる〔最初のコミットの後〕。マージは店主が全体用のアカウント `mateit-jp` で行う）。
- **古い行は直さない。** 間違いに気づいたら、日付つきの「訂正」の行を足し、直す前の行を残す。
- 「未確認」を「確認済み」に変えるときは、確認した日（JST）・コマンド・出力の要点・`rc` を同じ行に書く。出力が長いときは要点と場所だけにする。
- 状態は三つだけ。**「読めなかった」を「無い」「0件」と書かない。**
- 個人名・個人のメールアドレス・機体名・私的な置き場・業務の名前を書かない。`gh auth status` の全文を貼らない。回答の原文を写すときは個人名とメールアドレスを除く。
- 追記の後は、7 章の手順でリポジトリ全体の語の確認を流してから PR を出す。
