# 障害対応の手順（1枚）

止まった・おかしい・乗っ取られたかもしれない、のどれでも上から順に進める。
★急いで直すより、**間違った物を出し続けない**ことを先にする。★分からない所は「分からない」と書き残す。

## 1. 検知（何で気づいたかを書き残す）

| 気づき方 | 見る所 |
|---|---|
| Actions の失敗メール（deploy の build / deploy / verify） | Actions の画面で、どのジョブのどの手順が赤か |
| 外の見張り（`check_live.py`）が 1（違反）か 2（読めない） | 出力の「違反:」「確かめられませんでした:」の行 |
| 「更新が止まっています」の帯が出た | Actions の deploy の履歴（定期実行が動いているか・60日無活動で止まっていないか） |
| 利用者や権利者からの連絡 | 中身（どのページの何が、いつから） |

## 2. 切り分け（攻撃か・中の不具合か・元のデータか）

1. **公開中の中身が、検査を通った物と同じか**: 直近の deploy の verify が緑か（verify は公開のたびに全ファイルを
   今作った物と照合している）。手元で確かめるなら、時刻で変わらないファイルを比べる:
   `curl -s https://<公開URL>/style.css | shasum -a 256` と `shasum -a 256 site/static/style.css`（freshness.js・robots.txt も同じ）。
   ★HTML は「作った時刻」が入るので、手元で作り直した物とは必ず違う（比べても意味が無い）。
2. **身に覚えの無い変更が無いか**: GitHub の main のコミット履歴・Actions の実行履歴（誰が・いつ・何で起動したか）、
   Cloudflare の監査ログ（API トークンでのデプロイ・設定の変更）。
3. **元のデータの問題か**: 取得状況のページ（`/status.html`）と Actions の黄色の注記。unreadable が並んでいるだけなら、
   こちらは正しく「前回の内容」を出している。元の復旧を待つ（取得の頻度を上げて追いかけない）。
4. **配信の問題か**: Cloudflare のステータスページ。Cloudflare 全体の障害なら、こちらでできることは無い（2CDN 化は第3段階の検討事項）。

## 3. 乗っ取りを疑うときは、まず止めて全部取り替える

順番が大事（古い鍵が生きているうちに直しても、また書き換えられる）。

1. **公開を止める**: GitHub → Actions → deploy を Disable workflow（定期実行で書き戻されるのを止める）。
2. **鍵を全部取り替える**:
   - Cloudflare: その API トークンを Roll（作り直し）か Delete → 新しい値を `gh secret set CLOUDFLARE_API_TOKEN --env production --repo OWNER/REPO`
   - GitHub: このリポジトリを持つアカウントのパスワードと2要素の確認、不要な PAT・SSH 鍵・OAuth アプリ・GitHub アプリ（Claude を含む）の許可を見直す。
     ★怪しければ Claude GitHub App もいったん外す（クラウドのセッションは店主の名義で push できる）
   - ドメインを持っているなら: レジストラのパスワード・2要素・移管ロック
3. **確認済みの版から出し直す**: 乗っ取りより前の、自分で確かめたコミットを決める →
   そのコミットに戻す PR（`git revert`。★force push はしない）を main に入れる → deploy を Enable して Run workflow →
   verify（ヘッダ・帯・全ファイルの一致）が緑になるのを確かめる。
4. **残りを見る**: ruleset・Actions の設定・環境 production が変えられていないか（`sh repo_settings/check.sh OWNER/REPO`）。

## 4. 公表

- サイトの「このサイトについて」に、いつ・何が起きて・何を直したかを短く書く（個人情報・攻撃の手口の細部は書かない）。
- 間違った情報を出していた時間があれば、その時間帯と中身をはっきり書く。
- 権利者・公式から連絡が来ていれば、先にそちらへ返事をする。

## 5. 後で（落ち着いてから）

- 何が効いて何が効かなかったかを1行ずつ。検査で止められたはずなら、関所と試験と検算（`tests/mutation_check.py`）を足す。
- この手順書の直すべき所を直す。
