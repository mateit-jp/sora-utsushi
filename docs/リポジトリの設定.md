# GitHub のリポジトリ設定（画面で入れるときの一覧）

`repo_settings/apply.sh` と同じ中身を、画面で入れるときの手順にしたもの。入れたら `sh repo_settings/check.sh OWNER/REPO`
（読むだけ）で確かめる。★画面の文言は 2026-10 の公式文書から写した。画面が変わっていたら、意味の近い項目を選び、
違いを店主に伝える。

**前提**: リポジトリは **public**（無料で ruleset・CodeQL・secret scanning・push protection・非公開の脆弱性報告が使え、
Actions の標準の実行機も無料になる。private だと個人の Free では ruleset も CodeQL も使えない）。
★画面の操作は、すべてこのリポジトリを持つアカウントで行う（右上のアカウントを確かめる。別のアカウントで押したマージや
コメントは、その名前で公開される）。`repo_settings/*.sh` は、gh のアカウントが管理者でなければ何もせずに止まる。

## 1. Settings → General

- Features: Wikis を外す・Projects を外す（Issues は訂正の連絡のために残す）
- Pull Requests: Allow merge commits を外す／**Allow squash merging だけ残す**／Allow rebase merging を外す／
  **Automatically delete head branches** を入れる

## 2. Settings → Rules → Rulesets → New ruleset → New branch ruleset

- Ruleset name: `main を守る`／Enforcement status: **Active**／Bypass list: **空のまま**
  （★店主を入れると、店主の名義で動くクラウドの Claude Code も main へ直に push できてしまう）
- Target branches: Include default branch
- 入れる規則:
  - Restrict deletions
  - Require linear history
  - Require a pull request before merging（Required approvals は **0**。★1にすると、自分の PR を自分で承認できない
    GitHub の決まりのせいで、店主ひとりでは1つもマージできなくなる）／Allowed merge methods: Squash
  - Require status checks to pass: `test`・`wrangler-dry-run`・`zizmor` を足す
    （Require branches to be up to date は外す。deploy の build ジョブが main でもう一度全部検査するため）
  - Block force pushes
- ★Require signed commits は入れない（クラウドのコミットに署名が付く保証が無く、マージも止まりうる）

## 3. Settings → Actions → General

- Actions permissions: **Allow OWNER, and select non-OWNER, actions and reusable workflows**
  - Allow actions created by GitHub: 入れる／Allow actions by Marketplace verified creators: 外す
  - Allow specified actions and reusable workflows: `zizmorcore/zizmor-action@*`
  - **Require actions to be pinned to a full-length commit SHA**: 入れる
- Approval for running fork pull request workflows from contributors: **Require approval for all external contributors**
- Workflow permissions: **Read repository contents and packages permissions**／
  Allow GitHub Actions to create and approve pull requests: **外す**
- Artifact and log retention: 30 日

## 4. Settings → Environments → New environment `production`

- Deployment branches and tags: **Selected branches and tags** → `main` を足す
- Environment secrets: `CLOUDFLARE_API_TOKEN`（値は Cloudflare で作ったトークン。どこにも書き残さない）
- Environment variables: `CLOUDFLARE_ACCOUNT_ID`

## 5. Settings → セキュリティの欄（Advanced Security／Code security と表示される）

- Private vulnerability reporting: Enable
- Dependency graph: 入れる／Dependabot alerts: Enable／Dependabot security updates: Enable
- Code scanning → CodeQL analysis → Set up → **Default**
- Secret scanning: Enable／Push protection: Enable（個人の新しい public リポジトリは既定で入っているはず。確かめる）

## 6. Claude GitHub App（クラウドの Claude Code 用）

- このリポジトリを持つアカウントで https://github.com/apps/claude/installations/new → **Only select repositories** → このリポジトリだけ

## 入れない・使わないもの（理由）

| もの | 理由 |
|---|---|
| Bypass list に人を入れる | 店主の名義で動くクラウドのセッションも素通りになる |
| Required approvals を1以上 | 店主ひとりでは自分の PR を承認できず、何もマージできない |
| Require signed commits | クラウドのコミットの署名が Verified になる保証が無い |
| `pull_request_target` の workflow | fork のコードが秘密つきで動く（2026-11-02 から public では既定で止められる予定） |
| workflow の lockfile（`gh actions-lock`） | 2026-10-14 に preview。仕様が変わりうるので、正式になってから SHA 固定と置き換えるかを決める |
